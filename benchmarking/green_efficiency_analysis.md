Measurement Methodology:
I compiled a .c file using the gcc command to make it executable. I used the clock() functions with its start and end feature to measure how long each process took. I then converted the output into seconds using clocks per second. I ran this 3 times and took the average so we had a more accurate measurement of the time it took to execute each program.
Observed Performance Differences:
After taking the average time it took for the programs to run, I used the execution time to measure the performance difference between the 2 exercises. The baseline ran the program using one look and executed quickly. The naive algorithm used 2 loops. From the logic, we can see that there is a lot of repeated effort. This leads to time being wasted. This is confirmed with the execution times as the naïve algorithm takes longer than the baseline.
Relation Between Runtime and Energy Consumption:
There is a very direct relationship between runtime and energy. Any time a program is running, it is engaging the CPU. Any time the CPU is engaged, it is consuming energy in the form of electricity. So, the longer a program runs, the more energy it consumes. That is why it is very important to optimise our code to be more efficient. This makes sit more environmentally friendly and green. Between the 2 provided programs, the baseline did its work a lot quicker. The naive algorithm took longer for the same task and therefore consumed more power. 
Limitations of the Experiment:
While this method of measuring efficiency is an easy and simple way for comparing programs relatively, there are quite a few limitations to this method. Firstly, we are not measuring energy consumption. We are assuming that each program consumes the same amount of energy per second. This may not be the case. A program may use a lot more energy in a shorter time than another program consuming less energy over a longer time. The output is also not always the same so it may not be the most accurate.
Practical Engineering Takeaway:
Execution time is a great way to measure how our program stacks up compared to other programs. It can also be very helpful to make out code more efficient by trying to reduce its execution time. However, we need to take into account its shortcoming and be aware of what this method is lacking in terms of objective testing.
